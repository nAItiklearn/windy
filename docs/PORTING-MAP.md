# Porting map: macOS APIs used by Maccy -> Windows / Linux

Verification status: rows marked **[verified]** were checked against current upstream docs on 2026-10-30
(sources at the bottom). Rows marked **[to verify on device]** rest on well-known API behaviour but must be
confirmed by the manual matrix in `TEST-MATRIX.md` before the README claims them.

## 2. Password-manager / sensitive-data flags

| OS | Flag | Source | Windy rule |
|---|---|---|---|
| macOS | `org.nspasteboard.ConcealedType` | nspasteboard.org | skip copy (Maccy parity) |
| macOS | `org.nspasteboard.TransientType` | nspasteboard.org | skip copy |
| macOS | `org.nspasteboard.AutoGeneratedType` | nspasteboard.org | skip copy |
| Windows | `ExcludeClipboardContentFromMonitorProcessing` (any data) | Microsoft Learn **[verified]**: prevents "all clipboard formats being included in the clipboard history or synchronized" | skip copy |
| Windows | `CanIncludeInClipboardHistory` = DWORD 0 | same **[verified]** (value 1 = explicitly include) | skip copy |
| Windows | `CanUploadToCloudClipboard` = DWORD 0 | same **[verified]**: "does not affect the local device's clipboard history" | **not skipped on its own**: it is a sync flag, not a secrecy flag. Deliberate decision, recorded in `SECURITY-REVIEW.md` |
| Linux | `x-kde-passwordManagerHint` = `secret` | KDE Klipper / KeePassXC convention **[to verify on device]** | skip copy |
| All | user-editable ignored-types list (Maccy defaults kept, e.g. `com.agilebits.onepassword`) | Maccy | matched against format / MIME names |

These flags only help when the password manager sets them. Everything else is covered by the user's ignore regexes and ignored-apps list.

## 3. Hard parts, by OS

### Paste injection and focus return
- **Windows**: record the foreground HWND on hotkey. On select: hide popup, `SetForegroundWindow(prev)`, write clipboard, confirm the sequence number
  changed and modifier keys are released, then `SendInput` Ctrl+V. UIPI blocks injecting into elevated windows from a non-elevated Windy (documented).
  Terminals that paste with Ctrl+Shift+V are a known gap (a per-app paste key is not in Maccy; listed as an open question).
- **macOS**: Accessibility permission, prompt on first paste; `CGEventPost` with the ⌘ flag.
- **X11**: close the popup, return focus (`_NET_ACTIVE_WINDOW`), then XTEST.
- **Wayland**: copy-only unless a consented path exists.

### Race: paste before the clipboard write is visible
Always: write -> confirm our own sequence/serial changed -> bounded wait (<= 150 ms) -> inject.
Our writes carry a marker format (`Windy.Marker` on Windows, MIME `application/x-windy` on Linux, `org.windy.marker` on macOS) so the listener
treats them as "from Windy": bump the timestamp, keep the original source app, never create an unknown new item (mirrors Maccy's `fromMaccy`).

### Clipboard change events
- Windows: hidden listener window; ignore our own updates by marker.
- X11: XFixes selection notify; `INCR` transfers are capped by the size limit.
- Wayland, compatibility tables fetched 2026-10-30 from wayland.app:
  - `ext-data-control-v1` (staging): KWin 6.7, Sway 1.11, Hyprland 0.52.1, niri 26.04, COSMIC, Jay, Labwc, Mir, phoc, river, Treeland **yes**;
    **Mutter 51 no**, Muffin no, Weston, Wayfire, Cage, GameScope, Louvre no.
  - `wlr-data-control-unstable-v1`: marked deprecated upstream. Sway, Hyprland, COSMIC, niri, Wayfire, Labwc, river, Treeland yes; **KWin and Mutter no**.
  - Consequence: Windy implements `ext` first, `wlr` second. **GNOME/Wayland has neither**, so it needs an XWayland-based fallback. Whether Mutter's selection bridge
    reports Wayland-owned changes to an unfocused XWayland client has to be measured on Ubuntu and Fedora (**[to verify on device]**). If it fails, the README says
    "GNOME on Wayland: history only updates while a Windy window is focused".

### Global hotkeys on Wayland
`org.freedesktop.portal.GlobalShortcuts` (documented interface version 2): `CreateSession` -> `BindShortcuts` (id, `description`, optional `preferred_trigger`)
-> `Activated` signal. The portal "will typically" show a dialog, the returned set may be a subset or empty, and an app may bind once per session **[verified]**.
When unavailable Windy exposes `windy --toggle`.

### File clipboard items (cross-reference)
Windows `CF_HDROP`, Linux `text/uri-list`, macOS `public.file-url`. Windy canonicalises paths and rejects UNC (`\\host\share`), `file://host/...`, device paths;
it never resolves `.lnk`/`.url`/`.scf` (NTLM leak vector) and never follows symlinks. Details in `SECURITY-REVIEW.md`.
